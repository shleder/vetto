01 · rescue

Your transcript is fine.
The index is what breaks.

When Claude Code and Codex CLI lose history, the JSONL transcripts usually survive — the metadata index around them does not. One consolidated report in claude-code collected twelve independent reports and sixty reactions: hundreds of valid .jsonl files on disk, a fraction visible in the picker. vetto rescue reads the transcripts directly instead of trusting the index.

stable Codex adapter

Bounded, index-first discovery with explicit caps. scan, diagnose, snapshot, fork. Every snapshot is a verified new copy — SHA-256 checked, created exclusively, never overwriting, never writing inside the provider state root.

experimental Claude adapter

Treats provider JSONL as opaque until the format is independently verified. Requires an explicit root, fails closed on unknown state rather than guessing. Honest about what it does not know yet.

02 · sandbox

No boundary,
no process.

If the sandbox cannot be established, vetto refuses to launch your agent. There is no unsandboxed fallback, ever. Policy is resolved before exec; descendants inherit it; the network defaults to off.

  • Kernel-enforced, not prompt-enforced. Landlock, namespaces and seccomp on Linux; Seatbelt on macOS. An OS sandbox is a contract with the kernel, not a suggestion the agent may renegotiate.
  • Secrets stay secret. .env, keys and credential paths are masked before the agent can read them, and credential variables are stripped from the child environment by default.
  • Network off by default. Domain allowlists resolve outside the cell with DNS pinning. No TLS interception, no CA injection, nothing to abuse.
  • Evidence, not vibes. Session reports as JSONL, HTML, Markdown and SARIF; a CI mode with --fail-on-block; observation never widens policy.
Linux FULL Landlock + namespaces + seccomp Linux FS-only smaller boundary, fewer host needs macOS Seatbelt via sandbox-exec Windows experimental, capability-gated
03 · straight answers

Questions we would ask.

Why not just use the sandbox built into my agent?
Built-in sandboxes are tied to one tool, differ per platform and version, and ship escape hatches like dangerouslyDisableSandbox. vetto is one operator-controlled outer policy and one report model across Codex, Claude Code, Aider, opencode, custom scripts — without detecting or weakening whatever the agent does internally.
How is this different from landrun or ai-jail?
landrun is a general single-purpose Landlock wrapper for Linux. ai-jail wraps agents with bubblewrap/Landlock under GPL-3.0. vetto is a cross-platform daemonless binary (Linux tiers, macOS, experimental Windows) with fail-closed capability probing, network allowlisting through a DNS-pinned relay, SARIF evidence reports and the rescue surface — none of which are part of those projects.
There are tools that repair session indexes. Why rescue?
Index fixers rewrite vendor state, which is exactly what you should not do with the only copy of your work. vetto rescue is read-only diagnosis plus a verified copy-only snapshot of the raw transcript: the original is never modified, ambiguous or changing inputs fail closed, and output follows a versioned schema (rescue-output-v1). Repair stays possible later — destruction does not.
What does it cost in performance?
We deliberately publish no percentage claims — benchmarks without your workload are marketing. The overhead is bounded syscall/path checks after policy resolution. Measure on your machine: vetto doctor, then time the same command wrapped and unwrapped. The measurement rules live in docs/performance.md in the repository.
Why should I trust installing it globally?
Fair question for a security tool. The npm package ships only a launcher and prebuilt native binaries — there are no lifecycle scripts, no postinstall steps, and no runtime downloads. Every release asset carries a published SHA-256 checksum, builds are locked (cargo build --locked) from the Apache-2.0 sources, so everything is auditable and reproducible from the repository.
Does it work on Windows?
Windows support is real but experimental: a capability-gated AppContainer/restricted-token backend with network-off launches and inherited stdio. No domain allowlist relay and no multi-agent runtime there yet, and missing APIs stop the launch instead of degrading silently. Linux and macOS are the supported first platforms.
