# SLSA Build Provenance and Verification Guide

Every native release binary of `vetto` is built through automated CI and attested with cryptographic **SLSA Build Provenance (Level 3)** using GitHub's trusted build infrastructure and Sigstore.

---

## 1. Provenance Generation

During the automated release train workflow (`.github/workflows/release-train.yml`), native binary archives (`.tar.gz` and `.zip`) are signed using the official `actions/attest-build-provenance` action:

```yaml
- name: Generate SLSA Build Provenance Attestation
  uses: actions/attest-build-provenance@v1
  with:
    subject-path: release-assets/*
```

This binds each binary artifact to:
- The exact git commit SHA and release tag.
- The official workflow file running in `shleder/vetto`.
- The immutable cryptographic digest (SHA-256) of the compiled artifact.

---

## 2. How to Verify Downloaded Release Binaries

Operators can verify the provenance and integrity of any downloaded binary asset using the GitHub CLI (`gh`):

```bash
# 1. Download binary asset and sha256 checksum from GitHub Releases
gh release download v0.2.5 -p "vetto-linux-x86_64.tar.gz*"

# 2. Verify SLSA provenance attestation
gh attestation verify vetto-linux-x86_64.tar.gz --owner shleder
```

### Expected Output
```text
Loaded digest sha256:d5a6... for input vetto-linux-x86_64.tar.gz
Loaded 1 attestation from GitHub API with predicateType https://slsa.dev/provenance/v1
The attestation was generated by GitHub Actions in repository shleder/vetto
Verification succeeded!
```

If the binary was altered or compiled from an untrusted source, the verification command fails immediately.
